## 5. 真实崩溃恢复演练（杀进程 → `relay recover` 接管）

```powershell
relay run --chain <id> --detach          # 后台控制器
# …第一轮进行中时强杀控制器进程树…
taskkill /PID <controller_pid> /T /F
relay recover --dry-run                  # 列出待恢复链与锁归属
relay recover                            # 接管并继续
```

**结论：通过。** 工作链 `ch_b48e9ae495ab`（生产模式，真实项目 `agent-recap`），`state=complete`。

| 观察点 | 崩溃瞬间的实测状态 | 恢复后的结果 |
| --- | --- | --- |
| 工作链状态 | `running` | `complete` |
| 主会话数 | 1 个（`01a1c44f-2921-71f3-95ca-b172360c716c`） | **仍然是这 1 个**（`thread/resume` 重新挂载，**没有新建会话**） |
| 执行锁 | 归已死进程 `1095868`，心跳停在 15:14:44 | 被新控制器 `1096364` 回收 |
| 台账 | T1 已提交并标 `done`，`next=T2`（控制器还没同步就死了） | 直接从 T2 继续 |
| 模型请求 | 1 次（第一轮） | 累计 **2 次**，没有重复劳动 |
| 提交 | `c0897d6 feat: add recap version output…` | 追加 `d44fdea docs: explain version and status query behavior`，T1 未被重做 |
| 验收 | — | `node --test tests/recap.version.test.mjs` → **10 pass / 0 fail** |
| 报告 | — | `docs/reports/crash-recovery.md` |

关键日志证据：

```text
INFO environment ready
INFO reattached existing session      # thread/resume 挂载原线程
INFO active session reattached
INFO turn started                     # 从 T2 继续
INFO turn completed
INFO acceptance command finished
--- resuming ch_b48e9ae495ab
工作链 ch_b48e9ae495ab 结束: complete (complete)  turns=1 handoffs=0 model_requests=2
```

> 这次演练暴露并修复的真实缺陷（都已加测试或代码路径）：
> 1. **`--detach` 从未工作**：`relay run` 子命令缺 `--max-turns` 等参数，detach 出的子进程一启动就 `AttributeError` 退出，链停在 `pending`。已修，并让 detach 子进程继承预算参数。
> 2. **重启后无法驱动旧会话**：新 app-server 进程从未加载过旧 thread，`turn/start` 会失败。现在恢复时先 `thread/resume` 重新挂载（仍是同一个会话，不是新会话）；线程真丢失时才新建会话并递增序号（原来会与序号 1 冲突）。
> 3. **检查点只由压力驱动**：未跨阈值的链只有 `initial` 一个检查点，台账损坏就会丢进度。现在**每完成一个任务**再写一个 `task:<id>` 检查点。
