```powershell
relay run --chain <id> --detach          # 后台控制器
```

关键日志证据：

```text
INFO environment ready
INFO reattached existing session      # thread/resume 挂载原线程
INFO active session reattached
INFO turn started                     # 从 T2 继续
INFO turn completed
INFO acceptance command finished
--- resuming ch_b48e9ae495ab
工作链 ch_b48e9ae495ab 结束: complete (complete)  turns=1 handoffs=0 model_requests=2
```

> 这次演练暴露并修复的真实缺陷（都已加测试或代码路径）：
> 1. **`--detach` 从未工作**：`relay run` 子命令缺 `--max-turns` 等参数，detach 出的子进程一启动就 `AttributeError` 退出，链停在 `pending`。已修，并让 detach 子进程继承预算参数。
> 2. **重启后无法驱动旧会话**：新 app-server 进程从未加载过旧 thread，`turn/start` 会失败。现在恢复时先 `thread/resume` 重新挂载（仍是同一个会话，不是新会话）；线程真丢失时才新建会话并递增序号（原来会与序号 1 冲突）。
> 3. **检查点只由压力驱动**：未跨阈值的链只有 `initial` 一个检查点，台账损坏就会丢进度。现在**每完成一个任务**再写一个 `task:<id>` 检查点。

## 6. 生命周期命令与交付脚本

这一节把"代码里有、但一次都没被执行过"的命令补上了实测。

### 6.1 `relay pause` / `resume` / `stop`

单元测试（`tests/test_lifecycle.py`，零额度）覆盖关键约束：

- 已暂停的链**发起 0 次模型请求**就退出（需求"用户手动暂停时不得继续自动发起模型请求"）；
- `resume` 后能继续跑到结束；对非 paused 链 `resume` 抛错；
- `stop` 后 0 次请求，且对终态链幂等。

CLI 层冒烟（临时数据库）：

```text
$ relay --db <tmp.db> pause  --chain ch_92a89b01fc74   → ch_92a89b01fc74: paused
$ relay --db <tmp.db> resume --chain ch_92a89b01fc74   → ch_92a89b01fc74: running
$ relay --db <tmp.db> stop   --chain ch_92a89b01fc74   → ch_92a89b01fc74: stopped
$ relay --db <tmp.db> resume --chain ch_92a89b01fc74   → error: … is stopped, not paused (exit 1)
```

### 6.3 `install.ps1` / `uninstall.ps1`

完整跑了一次卸载 → 重装循环：

| 步骤 | 结果 |
| --- | --- |
| `uninstall.ps1` | 移除 `relay.exe`（`Test-Path` = False）、清理 hooks 块、清理安装器加的 PATH 条目；工作数据按约定保留 |
| 卸载后 | `where relay` 找不到（已真正卸载） |

## 8. 从检查点恢复（真实，而非 mock）


**结论：通过。** 台账被破坏后，控制器回退到最新有效检查点（`task:T1`），已完成的 T1 保留、未记录进检查点的 T2 回到 `pending`，并写了 `state_restored` 事件；模型请求数没有增加。

> **回退语义（重要）** — 恢复到的是"检查点里的状态"，因此检查点之后发生但还没写进检查点的进度会回退（本例中 T2 的完成被退回 `pending`，之后会重做）。这是有意的安全取舍：宁可重做一小步，也不基于可疑状态继续。
>
> 本轮还修掉一个由此暴露的不一致：恢复台账后没有把任务状态同步回数据库，导致 `task_results` 仍显示 T2 `done`。现在恢复时会一并同步。

## 9. 中途追加要求（新通道）

链的目标在启动时确定，之前没有任何"改需求"的入口。现在补上 `relay require` 与 MCP 工具 `relay_add_requirement`。

- `.relay/state.json` 的 `decisions` 追加一条（带 `recorded_by=operator`、时间戳）
